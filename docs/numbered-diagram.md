# 「番号から探す」の番号付き図面

## 実装範囲

番号一覧の上部画像に、既存座標JSONからSVGの枠線と番号を重ねます。図面は閲覧専用です。小さい図面で見たい場所を押すと、その位置を引き継いで番号付きの拡大画面を開きます。拡大画面内でも、見たい場所を1回タップすると周辺の番号を読める倍率へ拡大します。番号一覧の枠を押す登録・出庫操作は従来のままです。

| 変更前 | 変更後 |
|---|---|
| 図面を開いた直後は番号が0件。＋を複数回押す必要がある | 見たい場所を1回タップして、周辺番号を約14pxへ拡大 |
| 小さい図面で押した位置が引き継がれない | 押した画像上の位置を拡大画面へ引き継ぎ、中央付近へ移動 |
| 「番号109/205件表示」が画面内の件数に見える | 「図面全体の番号表示対象：109 / 205件」と明記 |

## 位置・大きさの計算

- `ParkingMapData.spotFile`、`validateSpots`、`measureSpots`、`containsPoint`、`clampMapPan` を再利用しています。
- 0〜100の相対座標を、実際の画像の幅・高さに応じたピクセル座標へ変換します。
- 各枠の重心・頂点平均・内部の候補点から、枠の外周と距離を取れる位置を選びます。凹形の枠にも対応します。
- 文字の桁数と、配置点から外周までの距離に合わせて文字サイズを決めます。白い縁取りを付け、画像の色に埋もれにくくします。
- 画像とSVGを同じ縦横比の親要素に入れ、SVGの`viewBox`（描画座標の範囲）も画像の実寸と一致させます。
- 画面上の文字が11 CSS px未満になる場合は省略します。拡大時も最大20 CSS pxに抑え、近接する文字の重なりを間引きます。

現地の枠と座標JSONの一致を再測量したものではありません。第3・第7の暫定表示は維持しています。

## 拡大画面

既存ライブラリPanzoom 4.5.1を別のインスタンスとして使います。「マップから探す」の自動拡大・操作モード・登録処理は変更していません。

- PC：クリックで自動拡大、＋／－、ホイール、ドラッグ、全体表示
- タッチ端末：タップで自動拡大、＋／－、ピンチ、ドラッグ、全体表示（実機操作は未確認）
- キーボード：図面にフォーカスして＋／－、矢印、0で全体表示。Escで閉じる
- 閉じると番号一覧へ戻り、拡大を開いたボタンに操作位置を戻します。
- 画像と番号を同じ親要素ごと拡大するので、両者の位置関係を保ちます。
- 枠内配置の計算は読み込み時に行います。移動だけの場合、番号の配置・表示判定は再計算しません。

小さい図面では番号がすべて省略される場合があります。見たい場所をタップすると、押した位置の周辺を読める倍率で開きます。キーボードで開く場合は位置を指定せず全体表示にします。画像の外の余白では開きません。

### 自動倍率と誤操作防止

1. タップ位置を元画像の座標へ変換し、表示上120px以内・近い順に最大8枠の番号を調べます。近くに枠がない場合は全体の番号サイズを参考にします。
2. 周辺の基準文字サイズの中央値を求め、その半分未満だけを極端に細い枠として倍率計算から除外します。通常の2桁・3桁の違いは除外しません。
3. 残る番号のうち小さい文字が約14pxになる倍率を計算します。既存の最大倍率を超えず、既に約14pxで読める場合は追加拡大も位置移動もしません。
4. タップ位置が中央へ近づく移動量を計算し、画像端で余白が出すぎないように補正します。画像とSVGは同じ親要素ごと動かします。
5. 最大倍率で目標に届かない場合と、極端に細い枠を除外した場合は、操作案内にその旨を表示します。

8px以上動いた操作、2本指操作、中断された操作をタップから除外します。ピンチ後の追加クリック、同じタップの二重実行も抑止します。閉じる・全体表示・手動操作では、待機中の位置引き継ぎを取り消します。

小図面からの引き継ぎは、新しい画面とPanzoomの初期表示を待ってから行います。閉じた画面や以前の駐車場へ遅れた処理が反映されないようにしています。

ブラウザによってクリックの座標が整数に丸められても拡大後の位置がずれないよう、タップ終了時の小数を含む座標を使用します。この差も自動テストと実Edgeで確認しています。

## 比較ページ・手動確認

確認専用サーバーは、架空の利用者と空き状況をメモリ上で使い、DBへ接続しません。127.0.0.1だけで待ち受けます。確認ページでの登録・出庫もメモリ上だけのシミュレーションです。

```powershell
node tests/helpers/numbered-diagram-preview.cjs "$env:TEMP\kari-autozoom-baseline-20261111"
```

ブラウザで `http://127.0.0.1:5179/review` を開きます。変更前ファイルの一時保存先が存在する間は、変更前後を並べて表示できます。引数を省略すると変更後だけ確認できます。

1. 第2駐車場を選び、小図面の100番付近を押す。その場所が拡大され、99番と100番の両方が表示されることを確認する。
2. ホイール・ドラッグ・全体表示を試し、番号が画像からずれないことを確認する。
3. 全6駐車場を順番に確認する。第3は706枠、第3・第7は暫定表示を確認する。
4. 幅390px・360pxの表示と、横向き相当の表示を確認する。
5. 図面を閉じ、空きの番号から予定時刻入力へ進む。取り消し・時刻あり・未定での登録を確認する。
6. 自分の番号から出庫確認へ進み、取り消し・出庫を確認する。
7. 「マップから探す」を開き、初回タップは拡大のみ、ピンチ・ドラッグ後に誤選択しないことを確認する。

### 実Edgeでの自動確認

確認用の隔離プロフィールと実際のPanzoom 4.5.1を使い、Edgeの表示領域を393×852・360×800・1366×768pxに指定して確認しました。新しいライブラリやアプリへの依存追加はありません。

- 全6駐車場：自動拡大、画像端での補正、番号の位置、＋／－、全体表示、ホイール、ドラッグ、合成ポインターによる2本指操作、小図面からの位置引き継ぎ
- 図面操作から駐車・出庫の送信が発生しないこと
- 既存の番号一覧からの時刻入力・駐車登録・自分の番号からの出庫（DB未接続の架空API）
- 既存マップの初回タップが自動拡大だけを行い、登録・送信を開始しないこと
- 案内文と閉じるボタンが画面内に収まること

第2の100番は3寸法とも約14pxで表示され、99番も表示されました。画面画像の確認で見出し色が暗かったため、この図面の見出しだけ文字色を継承する修正を行いました。

実行用スクリプト：

```powershell
node tests/helpers/numbered-diagram-browser-check.cjs "$env:TEMP\kari-autozoom-browser\panzoom-4.5.1.min.js" "$env:TEMP\kari-autozoom-baseline-20261111"
```

引数のJSは、アプリが既に利用しているPanzoom 4.5.1と同じ配信ファイルを一時保存したものです。変更前ファイルの引数は省略できます。結果と画面画像は`artifacts/numbered-autozoom/`に出力します。`comparison.html`で改善前後を比較できます。

実ブラウザを使った自動確認と画面画像の確認を実施しました。手動のPC操作、iPhone/Safari・Android/Chromeの実機の指操作、屋外での読みやすさ・実機での描画速度、実DBに対する登録・出庫は未確認です。

## 追加候補：番号一覧との連携

今回、ホバー・フォーカス連携は実装していません。難易度は中程度です。

おすすめは、マウスを重ねた番号とキーボードで選択中の番号に対応する枠を、図面上で強調する方法です。勝手に拡大・スクロールせず、現在の位置を保ちます。下部の番号要素は現在`div`なので、キーボード対応を追加する段階で`button`への変更と表示確認が必要です。

スマホの番号タップは従来どおり登録画面を開きます。「位置確認」を別の操作として追加する場合は、操作方法を相談してから実装するのが適切です。
