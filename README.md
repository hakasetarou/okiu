# okiu
大学の駐車場の空き情報がわかるサイトの作成

## 起動

WindowsのPowerShellでは、次のコマンドを使います。

```powershell
npm.cmd run migrate
npm.cmd start
```

ブラウザで `http://localhost:3000` を開いてください。
修正後は、起動中のサーバーを止めてから起動し直してください。

## 駐車場の設定

駐車場名、収容台数、画像パスは、PostgreSQLの `parking_lots` にまとめています。
`parking.js` はこの設定を読み込み、画面へ駐車場情報を返します。
地図の座標は引き続き `public/script.js` の `PARKING_SPOTS_DATA` にあります。

第5駐車場の収容台数は、利用者の確認に基づいて61台に設定しています。
余分に作成した旧22番の座標を削除し、旧23〜62番を新22〜61番に繰り上げました。
有効な61枠の位置と形は維持しています。DBの枠番号と駐車記録にも同じ番号変更を適用します。
古い地図画面が残っていると旧番号で登録されるため、修正後はサーバーを再起動し、
開いているブラウザの画面を再読み込みしてください。
新しいサーバーでは、旧番号体系の画面からの第5駐車場の登録を拒否し、再読み込みを案内します。
他の駐車場の台数は、以前のDB設定を維持しています。
第6駐車場は画像ファイルがないため、地図を開こうとすると案内を表示します。

`npm.cmd run migrate` は、駐車場IDの統一、同じ利用者・枠の重複防止、第5駐車場の61台への修正と番号変更を適用します。
適用済みの変更は再適用しないため、後からDBで変更した台数を上書きしません。
既存データが重複している場合は、削除せずにエラーで停止します。

## 確認

```powershell
npm.cmd test
```

DBテストは、接続先DB内にテスト専用の一時領域を作成し、終了後に削除します。
実際の利用者・駐車記録には書き込みません。DBへの接続と、一時領域を作成できる権限が必要です。
登録・再ログイン・出庫、同時登録の拒否、退庫予定の表示、通信失敗時の地図表示を確認します。

利用者の認証とパスワード保存は従来の方式です。今回の修正は駐車状態の整合性に関するもので、
公開運用に向けた認証セッションの導入とパスワードのハッシュ化は別途必要です。
