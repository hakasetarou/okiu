# okiu
大学の駐車場の空き情報がわかるサイトの作成

## 起動

WindowsのPowerShellでは、次のコマンドを使います。

```powershell
npm.cmd run migrate
npm.cmd start
```

ブラウザで `http://localhost:3000` を開いてください。
修正後は、起動中のサーバーを止めてから起動し直してください。

`parking.js` はこの設定を読み込み、画面へ駐車場情報を返します。
地図の座標は `public/data/parking-spots/lot-番号.json` に分けています。
第1駐車場の530枠は `lot-1.json` に初期座標を設定しました。
第2駐車場の205枠は `lot-2.json` に座標を設定しています。現地確認で木がある旧176番を除外しました。
枠番号はシステム用の連番で、現地の番号との対応は未確認です。
曲がった部分や端の枠には画像からの推定を含むため、下記の確認画像と設定画面で位置を確認してください。

`public/script.js` が選択した駐車場の座標を読み込み、全駐車場で同じ地図表示・入出庫処理を使います。
対象は第1・第2・第3・第4・第5・第7駐車場の6か所です。
地図がない第6駐車場は、一覧・合計台数・駐車登録の対象から削除しました。第7駐車場の番号は維持します。

第4駐車場は図面の78枠に座標を設定しています。第7駐車場は利用者が指定した2枠を追加し、エリアごとの1〜104番を設定しています。図面の93台との差は未確認のため、暫定104台と表示します。

古い画面から旧番号で入庫する操作を拒否するため、変更後はサーバーを再起動し、画面を再読み込みしてください。
第2駐車場は木がある旧176番を除外し、205台へ変更しました。旧177〜206番を新176〜205番へ繰り上げています。

利用者の指示に基づき、まず位置を確認するための706枠を暫定公開しています。
706台は現地で確定した駐車可能台数ではありません。図面の枠との対応を確認して修正します。
第7駐車場も、枠の片側が開いている図面を基に暫定104枠を公開しています。追加した2枠は新22・23番で、その下の曲がった列と合わせて22〜34番を付けています。既存102枠の位置は維持し、駐車記録にも同じ番号変更を適用します。現在の合計設定は1,684台です。

`npm.cmd run migrate` は、駐車場IDの統一、同じ利用者・枠の重複防止、第5駐車場の61台への修正と番号変更、第6駐車場の削除、台数の更新、第1駐車場の枠の追加・削除とエリアごとの番号変更、第2駐車場の木がある枠の除外・205台への修正と番号変更、第3駐車場の暫定706枠の公開、第4駐車場の78枠の公開前確認、第7駐車場の暫定102枠の初回公開と104枠への追加・番号変更を適用します。
適用済みの変更は再適用しないため、後からDBで変更した台数を上書きしません。
既存データが重複している場合は、削除せずにエラーで停止します。

## 他の駐車場の座標を設定する

`http://localhost:3000/coordinate-editor.html` を開いてください。
第1・第2・第4・第5駐車場は座標を設定済みです。第3駐車場は暫定706枠、第7駐車場は暫定104枠を設定済みです。
対象の6駐車場すべてに、マップから入出庫するための座標があります。
第3駐車場は[現在の番号付き確認画像](docs/lot-3-map-preview.png)と[確認事項・修正方法](docs/lot-3-map.md)を用意しています。マップを確認し、誤りを枠番号で指定して修正します。
実際の駐車枠の位置と番号を確認し、次の手順で追加します。

1. 駐車場と設定する台数を選びます。
2. 開始枠番号を入力し、地図上で枠の四隅を外周に沿ってクリックします。
3. 「囲んだ枠を保存」を押します。必要なら「拡大」で地図を拡大できます。
4. 同じ幅で並ぶ一列は「並んだ一列をまとめて囲む」でまとめて指定できます。
   表示される図の1→2→3→4の順に四隅を指定し、1→2へ向かって枠番号が増えるようにします。
   両面の列は片側ずつ指定し、幅が異なる枠は1枠ずつ囲みます。
5. 「座標ファイルを保存」で `lot-番号.json` をダウンロードします。
6. VS Codeの `public/data/parking-spots` にある同名ファイルを置き換えます。
7. 駐車場システムの画面を再読み込みし、「マップから探す」で位置と番号を確認します。

設定済みの番号を押すと編集できます。「指定番号を削除」ではその番号だけを削除し、
後の枠を自動で繰り上げません。「前の保存に戻す」で直前の編集を取り消せます。
作業途中の座標は同じブラウザに自動保存します。別のブラウザやPCへ移る場合はファイルを保存してください。
ファイルを置き換えるまで駐車場システムの地図には反映されません。

座標ファイルは次のような配列です。`id` が駐車枠番号、`polygon` が枠の角の位置です。
位置は画像の左端・上端を0、右端・下端を100として表します。
例えば `[10, 20]` は左から10%、上から20%の位置です。

```json
[
  { "id": 1, "name": "1", "polygon": [[10, 20], [15, 20], [15, 25], [10, 25]] }
]
```

座標の設定画面はDBの台数や駐車記録を変更しません。
登録可能台数は次のとおり設定しています。第3・第7駐車場は位置確認のための暫定値です。
`migrations/006-confirm-parking-capacities.sql` で画像に記載された台数へ更新し、
`migrations/007-lot1-map-correction.sql` で第1駐車場を一度532台へ変更します。
続いて `migrations/008-lot1-area-numbering.sql` で旧7番・旧133番を削除し、530台にしてエリアごとに番号をそろえます。
`migrations/009-lot2-remove-tree-space.sql` で第2駐車場の旧176番を除外し、205台と連番に修正します。
`migrations/010-lot3-provisional-map.sql` で第3駐車場を暫定706台にして表示用地図を切り替えます。
第3駐車場に駐車記録がある場合は、旧番号から位置を判断できないため、記録を維持して停止します。
`migrations/011-lot4-map-publication.sql` は第4駐車場の台数が78台で、駐車中の記録がないことを確認します。台数・画像・駐車記録は変更しません。
`migrations/012-lot7-provisional-map.sql` は第7駐車場を暫定102台にして表示用地図へ切り替えます。駐車中の記録がある場合は削除せず停止します。
続いて `migrations/013-lot7-area-numbering.sql` は指定された2枠を追加し、暫定104台にします。既存102枠の状態と入庫記録は、同じ位置を示す新番号へ移します。変更前の台数が102台でない場合、想定外の番号や重複する状態がある場合は、全変更を取り消して停止します。
削除する枠に駐車記録がある場合は、記録を削除せずに停止します。

| 駐車場 | 登録可能台数 | 補足 |
| --- | ---: | ---: |
| 第1 | 530 | エリアごとに1〜530番の連番を設定済み |
| 第2 | 205 | 木がある旧176番を除外し、1〜205番の座標を設定済み |
| 第3 | 706（暫定） | 1〜706番の座標を公開し、位置を確認中 |
| 第4 | 78 | 図面の78枠に1〜78番の座標を設定済み |
| 第5 | 61 | 61枠の座標を設定済み |
| 第7 | 104（暫定） | 指定された2枠を追加し、エリアごとの1〜104番を設定済み |

DBの収容台数を超える枠番号や、重複・不正な座標がある地図は開かず、確認を案内します。
設定途中でも有効な枠だけの地図を開けますが、未設定の枠は地図から選択できません。
全枠を設定してから、番号一覧との対応を確認してください。
地図では空き枠を緑、使用中を赤、自分の枠の外周を黄色で表示します。
緑の枠から入庫、自分の枠から出庫確認を開けます。他の利用者の枠から出庫はできません。

## 第1駐車場の座標と確認画像

[番号付きの確認画像](docs/lot-1-map-preview.png)と[設定内容・確認方法](docs/lot-1-map.md)を用意しています。
枠が多いため、第1駐車場のマップには番号を表示し、枠の外周線を細くしています。
この画像の緑色は位置を確認するための表示で、現在の空き状況ではありません。

`docs/lot-1-map-rows.json` は元画像上で測った列や枠線の位置です。
`scripts/build-lot1-map.js` はこの測定値から、画面で使用する530枠の座標ファイルを作ります。
通常の微調整は座標の設定画面で行い、保存した `lot-1.json` を置き換えてください。
測定値を変更して座標を作り直す場合は、次のコマンドを使います。

```powershell
npm.cmd run build:lot1-map
```

元の地図画像が変わった場合や、座標ファイルが手動編集されている場合は停止します。
手動編集を破棄して測定値から作り直す場合に限り、末尾へ `-- --replace` を付けてください。
DBの台数や入出庫記録は変更しません。

## 確認

```powershell
npm.cmd test
```

DBテストは、接続先DB内にテスト専用の一時領域を作成し、終了後に削除します。
実際の利用者・駐車記録には書き込みません。DBへの接続と、一時領域を作成できる権限が必要です。
登録・再ログイン・出庫、同時登録の拒否、退庫予定の表示、通信失敗時の地図表示を確認します。

利用者の認証とパスワード保存は従来の方式です。今回の修正は駐車状態の整合性に関するもので、
公開運用に向けた認証セッションの導入とパスワードのハッシュ化は別途必要です。
